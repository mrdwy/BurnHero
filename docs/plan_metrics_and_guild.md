# 数值与战队实施计划

## 范围与顺序

按 A→B→C→D 实现。当前只有 Vite/React 网页与本机 API 转发，无账号/社区后端；本地数据键保持 fat-burn-hero/v1 并增加可选字段，迁移不清空原角色。最新任务要求优先于旧版“取消校验/只转发”指令。演示模式恢复为可选入口，不配置 Key 也能测试。

1. A：新增集中配置、指标字典、硬/软校验与来源元数据、通用指标输入及橙色二次确认。接入建角、身体报告、手环、餐饮、记录页。增加克数/每百克联动、腰围和训练记录、冒险者手册；来源文档独立。
2. B：纯函数实现趋势体重、BMI/腰围模式、阶段、BMR/TDEE/缺口、活动/蛋白/饮水目标、自适应与速度判定。计划目标卡可点看算式；AI 只排任务，校验并覆盖模型数值；增加可离线演示的本地计划。
3. C：纯函数每日行为 XP、周上限、等级门槛、试炼、状态/装备百分比战力；领奖只结算当日累计新增行为经验，避免重生成/反复保存重复增长；固定难度奖励、周金币帽、趋势里程碑/维持奖励；一年模拟和单元测试。
4. D：可替换社区接口+本地mock；创建/邀请码加入/成员/队长转让/退出删除动态，模板BOSS/结算/贡献金币/加油战报。只投递字段白名单，不投递Key或原始照片。共享按类别默认不共享，开启前说明。入口放角色/首页，五格底栏不变。

## 待确认与本次默认

- **男性验收例有冲突**：72.1/1.75²=23.54，按指定BMI规则应为维持/塑形，最多0.25kg/周，BMR1680.75、TDEE2605.16、摄入2330.16（显示2330）。示例2054约等于0.5kg/周缺口，但不符合该BMI模式。先按明确公式/模式实现；单测同时固定正常腰围2330与中心型肥胖腰围时2055，不为了匹配近似值改BMI规则。
- 女性例 BMR1239、TDEE1486.8、缺口275后1211.8，下限托底1239，按公式实现。
- 正常BMI仍允许“最多0.25kg/周”；默认塑形取0.25，补给取0，减重取0.5。目标已达成进入守护者；低BMI优先补给，不因腰围覆盖。首阶段默认5%、周期6个月，可后续改配置。
- 新用户无14天步数时基线4000/1.1，显示4000。活动周目标150→最多300；日训练目标按周均摊，演示安排实际可记录的训练类型。
- TDEE校正仅在可用的14个日历日内至少10天完整三餐时执行；趋势斜率按14天首末变化/实际日期间隔折周。固定7700仅近似，不作为长期预测。
- 转职提案：20/40/60/80级记录个人基线与复测，STR坐站次数、END六分钟步行距离、AGI坐位体前屈、WIL连续完整记录天数；达到自身基线即可过门，待产品确认具体项目。本次实装记录基线/复测和门控；模拟明确假设每道试炼按时通过，否则严格停20级。
- 游戏设计取值：周金币500、单人日伤害40、战队4个演示队友起、12人上限、模板周HP按成员人数×每日目标伤害×7×70%；周金币分成按贡献，未击败给固定安慰金币。均集中配置并标设计值。
- 后端推荐：Supabase Auth+Postgres/RLS，手机号/邮箱登录，成本低、可审核行级授权；替代：自建Node+Postgres（控制强维护高）、Firebase（上手快但复杂查询/迁移成本）。本次不连接任何真实后端、不创建账号、不上传健康数据。mock队友只在本机模拟，邀请码不能跨电脑同步，页面明确标注。
- 二期仅规划：自愿开启的百分比榜单、提醒/复活卡/组队任务/推送。三期仅规划：挑战赛/广场/审核举报屏蔽敏感词。真上线前补隐私政策、健康数据独立同意、年龄确认。
